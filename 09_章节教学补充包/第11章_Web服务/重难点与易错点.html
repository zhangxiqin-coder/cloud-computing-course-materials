第 11 章 · Web服务
重难点与易错点

对应 教材 PPT：11.Web服务.pptx（103 页）｜ 课本 11 思考与练习 p.177

一、本章重点（必须掌握）

重点1
Web 体系：Web 是 Internet 上基于超文本的信息系统，核心由 Web 服务器、浏览器（客户端）和 HTTP 协议三者构成；Web 技术常被用作云计算服务的「实现介质」和「管理接口」。
重点2
C/S 与 B/S：C/S（客户机/服务器）需装专用客户端、安全性高但跨平台差、开发量大；B/S（浏览器/服务器）只需浏览器、跨平台好、开发量小，是云计算管理界面的主流形态。
重点3
页面技术：HTML 是 Web 页面基础；静态页面由 HTML 直接构成，动态页面靠 CGI、PHP、ASP、JSP、Servlet 等在服务端生成；脚本与插件增强交互与多媒体。
重点4
三层架构：UI（界面层）/ BLL（业务逻辑层）/ DAL（数据访问层），把界面、业务规则、数据访问分离，便于维护与分工，是逻辑上的三层而非必须三台机器。
重点5
URL 与 HTTPS：URL 由「协议://主机[:端口]/路径[?查询]#片段」组成；HTTPS = HTTP + SSL/TLS，提供加密传输与证书认证，是安全 Web 的基础；SLA/QoS 描述 Web 服务质量。

二、本章难点（讲慢一点、配比喻）

难点1
C/S 与 B/S 的取舍容易混：C/S 安全快但封闭、开发量大；B/S 跨平台但依赖网络与浏览器，要讲清各自适用场景。
难点2
静态页面与动态页面的本质区别：静态是「文件即内容」，动态是「程序运行时生成内容」，CGI/PHP/ASP/JSP 各自的运行位置（服务端）要讲清。
难点3
三层架构的「逻辑分层」与「物理部署」：三层是逻辑上的三层，可以部署在同一台机器，也可以分开，学生容易误以为必须三台服务器。

三、易错点（学生常错，务必提前点破）

易错1
以为 Web 只是「网页」——Web 是一整套技术体系（服务器 + 浏览器 + HTTP + 页面语言 + 架构），也是云计算的管理接口。
易错2
混淆 C/S 和 B/S——C/S 要装客户端、B/S 用浏览器即可，别把二者优缺点张冠李戴。
易错3
以为 HTML5 万能——它有跨平台、多媒体等优点，但也有安全（如 WebSocket 被利用）和浏览器兼容性问题。
易错4
把 SLA 和 QoS 当成一回事——SLA 是服务商与用户间的「协定/合同」，QoS 是实现该协定的「技术机制」。
易错5
以为 URL 只有「网址」——它由协议、主机、端口、路径、查询、片段多部分组成，端口常被省略但有默认值（http 80 / https 443）。
教师提示：建议把「易错点」单独投一屏，讲完知识点后立刻点破，比事后订正有效得多。
