第11章 Web服务 · 教案

教材：《云计算基础技术与应用(第2版)(微课版)》ISBN 978-7-115-66457-0

一、教学目的
  1. 理解 Web 服务的客户端 / 服务端模型，认识我们每天访问的网站背后就是云上的一堆 Web 服务。
  2. 掌握 Web 三层架构（表示层 / 业务逻辑层 / 数据层），理解 URL、HTML、HTTP、HTTPS、SLA、QoS 等核心概念。
  3. 第 3 课时完成一次动态网站（PHP + MySQL + Apache）部署实战，第 4 课时独立完成本章随堂练习。
二、重点、难点及处理方法

教学重点：

  1. Web 客户端与服务端模型，请求—响应过程。
  2. 三层架构及各层职责。
  3. HTTP 与 HTTPS 的区别、URL / HTML / SLA / QoS 的作用。

教学难点：

  1. 「请求—响应」的来回过程看不见、摸不着，难想象。
  2. 三层架构（表示 / 业务 / 数据）的边界与协作关系易混。
  3. HTTPS 为什么比 HTTP 安全（加密 / 身份认证）难讲透。

处理方法：

  • 用「去餐厅点菜」比喻请求—响应——顾客（客户端）下单，厨房（服务端）出菜，菜单即 HTTP 请求；用「包厢 / 大厅 / 仓库」比喻三层架构。
  • 用「寄平信 vs 寄挂号加密信」比喻 HTTP（明文）与 HTTPS（加密 + 证书），回扣第 5 章安全内容。
  • 第 3 课时把网站跑起来，让学生用浏览器真正访问到自己部署的页面，把抽象协议变成「点开就看到」。
三、教具

机房电脑 + 多媒体投影 Web 服务部署环境（LAMP：Apache+PHP+MySQL，教师预装或在线沙箱；无安装权限则教师机投影演示） 黑板 +「Web 三层架构」图 +「HTTP vs HTTPS」对照表

四、课时分配

1、 讲课：Web 服务的客户端和服务端 + 三层架构（1 课时）
2、 讲课：Web 服务相关知识（URL / HTML / HTTP / HTTPS / SLA / QoS）（1 课时）
3、 实战：PHP + MySQL + Apache 动态网站服务部署（1 课时）
4、 随堂练习 + 讲解练习情况（1 课时）

五、作业

1、 完成随堂练习中当场未做完的题目（课本第 11 章「思考与练习」原题，教师投影题目或印发，学生纸上作答）。
2、 用一句话说明 HTTP 与 HTTPS 的区别，并各举一个你会用到的场景。
3、 整理第 3 课时部署动态网站的 1 句操作记录（如「装好 Apache，浏览器访问到测试页」）。

六、教学过程
1
讲课：客户端 / 服务端 + 三层架构
教材原版 PPT 第11章 4–34 页 ｜ 90 分钟
环节教学活动
引入教师：提问「你刷的网页，数据从哪来？为什么输入地址就能看到内容？」引出客户端 / 服务端。
讲解教师：讲 Web 客户端（浏览器）与服务端（Web 服务器）的职责、请求—响应模型；讲 Web 三层架构（表示层 / 业务逻辑层 / 数据层）及各层职责。
互动师生：全班口头接龙，每人说一个「你用浏览器干过的事」（看视频、下单、查成绩），教师用「餐厅点菜」比喻把请求—响应过程画在黑板。
收口教师：小结客户端 / 服务端与三层架构；预告下节课讲 HTTP / HTTPS 等概念，之后亲手部署网站。
2
讲课：URL / HTML / HTTP / HTTPS / SLA / QoS
教材原版 PPT 第11章 35–99 页 ｜ 90 分钟
环节教学活动
引入教师：投影一个网址，问「这一串字符每部分是什么意思？为什么前面有时是 http 有时是 https？」
讲解教师：逐个讲：URL（资源地址）、HTML（网页结构语言）、HTTP（明文传输协议）、HTTPS（加密 + 证书的安全协议，回扣第 5 章）、SLA（服务等级协议，厂商对可用性的承诺）、QoS（服务质量）。
互动师生：教师把「HTTP vs HTTPS」对照表画在黑板，请学生口头补全（是否加密、是否有证书、典型场景），点破易错点（HTTPS 不是另一种协议而是 HTTP + 安全层）。
收口教师：一句话总结「这些概念共同撑起你每天用的网站」；点明下节课把网站真正跑起来。
3
实战：PHP + MySQL + Apache 动态网站部署
教材原版 PPT 第11章 100–102 页 ｜ 90 分钟
环节教学活动
布置教师：说明实战目标——搭建一个最小的动态网站（Apache 提供 Web 服务、PHP 处理逻辑、MySQL 存数据），用浏览器真正访问到自己部署的页面，把三层架构变成「点开就看到」。环境由教师预装（LAMP）或用在线沙箱；机房若不可安装则改用教师机投影演示完整部署流程，学生记录。
实操电脑学生（分步完成）：
① 启动 Apache 服务，浏览器访问测试页确认 Web 服务在线；
② 放置一个简单 PHP 页面，访问看到动态输出；
③ 连接 MySQL，验证数据层可用；
④ 回扣三层架构：浏览器=表示层、PHP=业务层、MySQL=数据层。
巡堂教师：走动答疑，收集典型问题（如服务起不来、页面空白），投屏演示；无环境的机位统一看教师机操作。
收口教师：请 1–2 组展示自己访问到的网页，点出「你刚部署的，就是云上千万网站的最小形态」。要求每人留 1 句操作记录进笔记。
4
随堂练习 + 讲解练习情况
课本第11章「思考与练习」原题（教师投影 / 印发）｜ 90 分钟
环节教学活动
练习学生：完成课本第 11 章「思考与练习」原题（教师投影题目或印发，学生作答于作业本）。教师计时，约 35–40 分钟独立完成。
收看教师：巡堂收看完成情况，标记错误率高的题目（通常集中在三层架构、HTTP / HTTPS 区别）。
讲解教师：挑选错误率最高的 6–8 题重点讲解，公布答案要点，让学生对照订正。
收口教师：回扣本章易错点做总结；未做完的题作为作业补完。
七、课后小结
人工智能241班：应到 38 人，实到 38 人（全勤）。课时 1–2 客户端 / 服务端、三层架构达成度较好，餐厅点菜比喻接受快；HTTP / HTTPS 区别、SLA / QoS 概念仍是难点。课时 3 网站部署实战多数访问到测试页（约 5 组无环境改看演示），「亲手点开自己部署的网页」效果好。课时 4 随堂练习三层架构类题正确率约 78%，HTTPS 场景题失分较多，已现场重讲。下次：三层架构图、HTTP/HTTPS 对照表提前发，部署前先空跑一遍流程。

（按实际授课班级填写：到课情况、目标达成度、随堂练习正确率、易错点是否讲透、下次调整建议）
