第 3 章 · 云计算的部署
云部署模型实战 · 图文走查版

适用场景：机房不便注册账号 / 限制联网时，由老师按真实控制台步骤现场演示，学生对照本页截图位与关键画面做记录，照样完成本章实战。无需人人实名、不付费。

师生分工：蓝条＝老师演示动作；黄条＝学生要看 / 要记的内容。每页留「截图位」和「学生记录栏」，下课前收作实验报告。
云部署模型实战（走查版，与真操版步骤一致）
最终目标：看清「在公有云控制台自助开通一个资源」的全过程，并理解它属于「公有云」部署；能说出责任共担分工与三种部署模型的区别。
▌ 第一步：控制台参观 + 登录
老师演示：① 打开 阿里云控制台 https://home.console.aliyun.com（或腾讯云），用演示账号登录；② 指出首页的产品分类（计算 / 存储 / 网络 / 数据库）；③ 点开「地域与可用区」说明云资源分布与「自助开通」的含义。
学生看：控制台就是「自助管理云资源的网页后台」，它对应的正是公有云「按需自助服务」特征。
[ 截图位 ①：控制台首页，框出产品分类与地域选择器 ]
学生记录：控制台首页能看到的产品大类有 ________、________、________（提示：计算/存储/网络/数据库）。
▌ 第二步：开通一个免费资源——对象存储 OSS 存储桶
老师演示：① 产品与服务 → 对象存储 OSS → 创建 Bucket；② 填名称（如 class-photo-demo）、选地域、读写权限选「私有」；③ 进入 Bucket 上传一张示例图片；④ 把权限改成「公共读」再对比。
学生看：上传后控制台给出的「文件 URL」和「存储类型」——这就是亲手开通的公有云存储资源；权限从私有改公共读，说明「权限配置」是用户的责权。
[ 截图位 ②：OSS Bucket 创建成功 + 文件已上传，能看到文件 URL ]
学生记录：本次开通的资源类型是 ________（提示：对象存储/OSS）；Bucket 读写权限先设为 ________，后改为 ________。
▌ 第三步：责任共担识别（核心）
老师演示：在控制台里指出这些项，逐项问「归云厂商还是归用户」：物理机房/网络设备、虚拟化层漏洞修复、操作系统补丁、账号密码保管、数据备份策略。
学生看：记住口诀——「云厂商管下层（基础设施），用户管上层（数据与应用）」。
项目负责方
物理机房 / 网络设备云厂商
虚拟化层 / 云产品自身漏洞修复云厂商
操作系统补丁 / 应用安全用户
账号密码 / 访问密钥(AK) 保管用户
数据加密 / 备份策略用户（可借助厂商工具）
学生记录：写出 2 条「归用户负责」的项：________、________。
▌ 第四步：部署模型归类与设计
老师演示：给出一个场景（班级相册 / 选课系统），分别用 公有云 / 私有云 / 混合云 三种方式描述部署，并展示对比表。
学生看：混合云＝公开内容放公有云、敏感数据放校内私有云；并判断教师举的例子（微信云开发、校内财务服务器、政务混合云、行业联盟）各属哪种模型。
部署方式怎么部署成本安全可控适用
公有云全部用阿里云 OSS + ECS低（按量）中快速上线、弹性
私有云学校自己机房服务器高（一次性）高数据敏感、合规
混合云公开照片放公有云 + 信息放校内私有云中高兼顾弹性与隐私
学生记录：「学校财务系统内网服务器」属于 ________ 云；「政务系统敏感数据校内+对外公有云」属于 ________ 云。
理解检查（口头回答即可）：刚才开通的 OSS 桶属于哪种部署模型？——答：公有云。责任共担里，云厂商管什么、用户管什么？——答：厂商管下层基础设施，用户管上层数据与应用。
走查验收清单（学生提交本页即过关）：

  • 四个「学生记录栏」已填写
