第 7 章 · 计算机网络
上机实操指导

机房环境：可上网、不可安装软件，全部实操基于网页 / 在线工具 / 系统自带命令

机房纪律：① 一律不安装任何软件，网站要求下载客户端时点「网页版」；② 涉及云厂商页面只看不买，绝不点付款；③ 下课前必须退出登录，浏览器问「是否保存密码」一律选「从不」。
实验一：用系统命令查看本机网络配置
目标：认识 IP 地址、子网掩码、默认网关，判断地址类别并分离网络号与主机号。
操作步骤：
  1. 按 Win+R，输入 cmd 回车，打开命令提示符。
  2. 执行 ipconfig /all，在输出中找到「以太网适配器」或「无线局域网适配器」。
  3. 记下四项：IPv4 地址 / 子网掩码 / 默认网关 / DNS 服务器。
  4. 根据第一个字节判断地址类别（A/B/C），并写出网络号与主机号。
验收清单：
  • 找到 IPv4 地址、子网掩码、默认网关
  • 能判断 A/B/C 类地址
  • 能正确写出网络号与主机号
打不开 / 完不成：若机房禁用 cmd，可走「设置 → 网络和 Internet → 状态 → 属性」查看网络配置。
实验二：用 ping 和 tracert 理解网络连通性与路由
目标：通过命令行工具体会网络层连通性测试和路径追踪。
操作步骤：
  1. 在 cmd 中执行 ping www.qq.com，观察是否收到回复、平均往返时间是多少。
  2. 再执行 tracert www.qq.com，观察从本机到目标经过了多少个路由跳点。
  3. 对比两个命令：ping 测什么？tracert 测什么？分别对应 TCP/IP 的哪一层功能？
验收清单：
  • ping 通目标并看到往返时间
  • tracert 至少显示 3 跳
  • 能说出 ping 测连通性、tracert 看路由路径
打不开 / 完不成：部分校园网可能禁用 ICMP，ping 不通不代表网络真的断开，可以换 DNS 服务器地址 114.114.114.114 再试。
实验三：浏览器 Network 面板看 TCP 连接建立（替代 Wireshark 抓包）
目标：在浏览器里直观看到 DNS、TCP 握手、TLS 加密的过程，理解传输层与应用层的关系。
操作步骤：
  1. 打开 Chrome/Edge，按 F12 打开「开发者工具」，切换到 Network（网络）面板。
  2. 地址栏输入 https://www.qq.com 并回车。
  3. 点击第一个请求（通常名称是 qq.com 或 www.qq.com），查看 Timing 标签。
  4. 找到 DNS Lookup、Initial Connection、SSL 三个阶段，记录各自耗时。
  5. 讨论：Initial Connection 里包含了 TCP 三次握手，SSL 阶段完成了加密协商。
验收清单：
  • 打开 Network 面板并刷新页面
  • 点击请求看到 Timing 标签
  • 找到 DNS/Initial Connection/SSL 三个阶段
打不开 / 完不成：不同浏览器菜单位置略有差异，关键是找到 Timing 或「计时」标签。
