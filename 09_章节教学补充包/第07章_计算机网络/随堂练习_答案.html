一、单项选择题

1. IP 地址 200.64.32.65 的主机号是（　）。
答案：D
200 开头为 C 类地址，默认子网掩码 255.255.255.0，网络号是 200.64.32，主机号是 65。
2. 在 TCP/IP 中，TCP 工作在（　）。
答案：B
TCP（传输控制协议）与 UDP 一样，都工作在 TCP/IP 模型的传输层。
3. 计算机网络建立的主要目的是实现计算机资源共享，计算机资源主要指（　）。
答案：C
计算机资源包括硬件资源、软件资源和数据资源三大部分。
4. 在 TCP 三次握手过程中，正确的步骤顺序是（　）。
答案：B
三次握手的标准流程：SYN → SYN-ACK → ACK，目的是同步初始序号并确认收发能力。
5. 下列关于 UDP 和 TCP 的叙述中，不正确的是（　）。
答案：C
TCP 的核心价值正是可靠传输，并提供流量控制与拥塞控制；C 与事实相反。
6. Internet 最早起源于（　）。
答案：A
Internet 的前身是美国国防部高级研究计划局建立的 ARPANET。
7. 以下 IP 地址中，属于 B 类地址的是（　）。
答案：C
B 类地址第一个字节范围是 128–191，只有 131.107.2.89 符合。
8. 关于 IP 提供的服务，下列说法正确的是（　）。
答案：A
IP 层只负责尽力而为的分组转发，不保证可靠、不保证顺序，可靠性由 TCP 等上层协议实现。
9. 企业 Intranet 要与 Internet 互联，必需的互联设备是（　）。
答案：D
不同网络之间的互联需要三层路由设备，即路由器。
10. 在 TCP/IP 中，UDP 工作在（　）。
答案：B
UDP 与 TCP 同处传输层，只是它无连接、不保证可靠。

二、简答题

1. TCP 和 UDP 在网络通信中各自扮演什么角色？
答案：TCP 是面向连接的传输层协议，提供可靠、按序、流量可控、拥塞可控的字节流传输，适合文件传输、网页浏览、邮件等对可靠性要求高的场景。UDP 是无连接的传输层协议，不保证可靠、不保证顺序，但开销小、时延低、传输效率高，适合视频直播、在线游戏、DNS 查询等对实时性要求高、可容忍少量丢包的场景。
从「连接方式、可靠性、传输效率、适用场景」四个维度对比。
2. 为什么需要三次握手和四次挥手的过程来确保数据传输的可靠性？
答案：三次握手用于建立连接：第一次客户端发 SYN，让服务器知道客户端请求建立连接并告知初始序号；第二次服务器回 SYN-ACK，告知自己的初始序号并确认收到客户端请求；第三次客户端回 ACK，确认收到服务器响应。这样双方都能确认收发能力正常且初始序号同步，防止历史重复连接。四次挥手用于释放连接：TCP 是全双工的，每一方向对方发送完数据后都要单独发 FIN 并等待 ACK，因此需要四次报文才能彻底关闭两个方向的通道，避免数据丢失。
重点讲清「全双工」导致关闭需要四次，以及「同步初始序号 + 防止历史连接」是三次握手的目的。
3. 拥塞控制和流量控制这两种控制机制在网络通信中分别起到什么作用？
答案：流量控制是端到端的控制机制：接收方根据自己缓存大小告诉发送方还能接收多少数据，防止发送方过快导致接收方缓存溢出，典型实现是滑动窗口。拥塞控制是面向整个网络的控制机制：发送方根据网络拥塞程度（如丢包、时延增大）动态调整发送速率，防止过多数据注入网络造成路由器队列溢出、全网性能下降，典型实现包括慢启动、拥塞避免、快重传、快恢复。
用一句话区分：流量控制是「别让接收方撑死」，拥塞控制是「别让网络堵死」。
4. TCP/IP 在安全性方面存在哪些潜在的问题？
答案：① 数据在传输过程中可能被窃听：TCP/IP 本身不加密，数据以明文或可被截获的方式经过多个中间节点。② 数据可能被篡改：缺乏内置完整性校验时，中间人可修改报文内容。③ 身份认证不足：早期协议缺乏对通信双方身份的强认证，容易出现伪装、欺骗（如 IP 欺骗、ARP 欺骗）。④ 协议本身漏洞：如 SYN Flood 攻击利用三次握手消耗服务器资源，ACK 欺骗、序列号猜测可导致连接劫持。⑤ 应用层安全问题：协议栈下层不替应用层解决所有安全问题，应用层需额外做加密、认证、访问控制。
从「窃听、篡改、身份认证、协议漏洞、应用层责任」五个角度组织答案。
5. 分析 IPv6 相对于 IPv4 的主要改进，并讨论 IPv6 在推广过程中遇到的挑战和可能的解决方案。
答案：主要改进：① 地址空间极大扩展，由 32 位增至 128 位，从根本上解决地址枯竭。② 报文首部简化，固定 40 字节基本首部，路由转发效率更高。③ 内置安全性，IPsec 成为标准组成部分，支持端到端加密和认证。④ 支持无状态自动配置与即插即用，终端接入更便捷。⑤ 支持移动性，节点在不同网络间移动时保持连接。推广挑战：① IPv4 设备存量巨大，全网升级成本高。② NAT 技术缓解了 IPv4 地址短缺，降低了部分场景的升级动力。③ 网络运营商、应用开发商、终端用户协调困难。④ 部分老旧应用和设备不兼容 IPv6。解决方案：双栈部署（IPv4/IPv6 同时运行）、隧道技术（在 IPv4 网络中封装 IPv6 报文）、政府与行业推动、逐步替换老旧设备、培养网络人才。
改进要突出「地址空间、首部简化、安全、自动配置、移动性」；挑战要答出「存量设备、NAT 惯性、协调困难、兼容性」。
