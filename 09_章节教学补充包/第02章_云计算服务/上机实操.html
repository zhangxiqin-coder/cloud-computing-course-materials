第 2 章 · 云计算服务
Gitee 代码仓库课堂实操

机房环境：可上网；电脑若已预装 Git 则走命令行（init / add / commit / push / clone / pull），未装 Git 则改用 Gitee 网页版「上传文件」完成等价操作。

机房纪律：① 不自行安装软件；Git 已预装就用命令，没装就走网页版；② 只在 Gitee 练习，绝不点任何付费按钮；③ 下课前退出登录，浏览器问「是否保存密码」一律选「从不」。
Gitee 云端代码仓库（对应教材实战项目 · 全程用 Git 命令）
目标：用 Git 把本地文件 推（push）到 Gitee、再从 Gitee 拉（pull / clone）回本地，体会「开发者视角的云服务」，并分清 push / pull / clone 各自做什么。
▌ 第一步：在 Gitee 建仓库（网页，1 分钟）
  1. 打开 https://gitee.com，用手机号或邮箱注册并登录。
  2. 点右上「+ → 新建仓库」，名称填 cloud-02，不要勾选「初始化 README」（方便本地推送），私有或公开均可。
  3. 建好后复制仓库地址（页面上 HTTPS 那一栏）。
▌ 第二步：本地初始化，第一次 push（上传到云）
在机房电脑的命令提示符 / 终端依次输入：
mkdir cloud-02 && cd cloud-02 git init git config user.name "你的名字" git config user.email "你@gitee.com" echo 云计算第2章实验 > readme.txt git add readme.txt git commit -m "第一次提交" git remote add origin https://gitee.com/你的名/cloud-02.git git push -u origin master
预期：刷新生效后，Gitee 网页仓库里出现 readme.txt，提交记录 +1。
▌ 第三步：修改文件，再 push 一次（更新云端）
echo 新增一行内容 >> readme.txt git status # 看到 readme.txt 被修改（红色） git add . git commit -m "第二次提交" git push
预期：提交记录变成 2 条，云端文件内容同步更新。
▌ 第四步：换台电脑 / 新文件夹，clone 拉取（整仓库下载）
cd .. git clone https://gitee.com/你的名/cloud-02.git cloud-02-copy cd cloud-02-copy type readme.txt # Linux / Mac 用：cat readme.txt
预期：新文件夹里出现和云端一模一样的 readme.txt——这就是「从云上整仓库下载」。
▌ 第五步：团队协作，pull 拿回别人的改动（同步）
cd cloud-02-copy echo 同学加的内容 >> readme.txt git add . && git commit -m "同学修改" && git push cd ../cloud-02 git pull # 把云端同学的新改动拉回本地
预期：原文件夹的 readme.txt 也多出那一行——push 与 pull 合起来就是多人协作的「上传 + 同步」。
验收清单：
  • Gitee 仓库创建成功
  • 本地 git push 成功，提交记录 ≥ 2 条
  • git clone 能把仓库整份拉到本地新文件夹
  • git pull 能把云端新改动同步回本地
  • 能说清：push＝上传、pull＝下载同步、clone＝整仓库下载、commit＝本地存档
打不开 / 完不成：① 收不到验证码，先用老师准备的公共账号参观，重点看「提交记录」页；② 机房若没装 Git，改用 Gitee 网页「上传文件」按钮完成「推」，用「Web IDE」查看文件——命令能跑就尽量跑，更能体会开发者视角，对应 IaaS / PaaS 之外的「代码托管 SaaS」。
